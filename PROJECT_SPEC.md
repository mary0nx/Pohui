# Family OS — спецификация продукта

Family OS — частное цифровое пространство семейной пары, доступное как Telegram Mini App
и через Telegram-бота. Рассчитано на двух партнёров, но модель данных поддерживает
произвольное число участников семьи.

Документ описывает **требования**. Фактический статус реализации — в `TASKS.md`.

## 1. Пользователи и роли

| Роль    | Права |
|---------|-------|
| `owner` | Всё, включая удаление семьи и управление ролями. Создатель семьи. |
| `admin` | Управление участниками (кроме owner), приглашениями, настройками семьи. |
| `member`| Работа с данными семьи, выход из семьи. |

* Публичной регистрации нет. Пользователь появляется в системе после первой
  проверенной Telegram-авторизации.
* Присоединиться к чужой семье можно только по действующему приглашению.
* Пользователь может состоять в нескольких семьях (архитектурно), интерфейс работает
  с одной «активной» семьёй.

## 2. Видимость данных

| Уровень | Кто видит |
|---------|-----------|
| `family` | Все участники семьи. |
| `private` | Только автор записи. Запись не попадает партнёру ни в списки, ни в сводки, поиск, AI-контекст, уведомления, историю изменений. |

Уровень `shared_with_members` предусмотрен в модели авторизации, но в v1 не
используется ни одним модулем (для двух участников он эквивалентен `family`).

Значения по умолчанию: финансы, календарь, задачи, покупки — `family`; личные заметки,
журнал и список желаний — `private`; документы — `family` с явным выбором при загрузке.

## 3. Модули

### 3.1 Главная (dashboard)
Реальные данные из backend: приветствие, семья, доходы/расходы/баланс месяца,
остаток бюджета, ближайшие события, просроченные и ближайшие платежи, покупки,
незавершённые задачи, активные цели, последние изменения, быстрые действия,
вход в AI. Пустой аккаунт видит подсказки «добавьте первые данные».

### 3.2 Финансы
* Операции: доход, расход, возврат, перевод между своими счетами.
* Поля: сумма (Decimal, `NUMERIC(14,2)`), валюта, счёт, категория/подкатегория,
  дата и время, описание, получатель/магазин, способ оплаты, автор, видимость,
  прикреплённый чек (документ).
* Переводы не учитываются в доходах и расходах. Возвраты уменьшают расходы.
* Счета: наличные, банковский (ручной ввод), карта, сбережения, другое; начальный
  остаток, расчётный текущий остаток.
* Бюджеты: общий месячный лимит и лимиты по категориям, план/факт, предупреждения
  при 80 % и 100 %, копирование бюджета с прошлого месяца, история.
* Регулярные платежи: правило повторения хранится отдельно от фактических платежей
  (`recurring_rules` → `scheduled_payments` → `transactions`). Повторный запуск
  фонового задания не создаёт дубликатов (уникальность `(rule_id, due_date)`).
* Накопления: цель, сумма, дата, история пополнений, прогноз по средней скорости.
* Импорт CSV. Подключение банков не входит в MVP и не изображается работающим.
* Сводки считаются в основной валюте семьи; операции в других валютах показываются
  отдельно и не конвертируются (курсов валют в v1 нет).

### 3.3 Календарь и напоминания
* Общие и личные события, описание, начало/конец, весь день, место, категория.
* Повторение: ежедневно/еженедельно/ежемесячно/ежегодно, интервал, дата окончания;
  отмена отдельного повторения.
* Подтверждение участия (RSVP) участниками семьи.
* Напоминания за N минут до события, доставка в Telegram.
* Время хранится в UTC, повторения вычисляются в часовом поясе события, поэтому
  переходы на летнее/зимнее время не сдвигают «настенное» время события.
  Часовой пояс по умолчанию — `Europe/Warsaw`, настраивается для семьи.

### 3.4 Списки покупок
Несколько списков, архивирование, товары с количеством, единицей, категорией,
комментарием, ценой, магазином, статусом, кто добавил/купил, история изменений,
быстрое и массовое (из текста) добавление, формирование из плана питания.
Синхронизация между участниками через backend (периодическое обновление).

### 3.5 Домашние задачи
Исполнитель (или общая задача без исполнителя), срок, приоритет, категория,
повторение, статусы, комментарии, история, напоминания, фильтры. Необязательные
очки отображаются только как **общий** результат семьи — без рейтингов партнёров.

### 3.6 Продукты, рецепты, меню
Запасы с количеством и сроком годности, рецепты с ингредиентами и порциями,
недельное меню, формирование списка покупок из меню с учётом запасов.
AI может предложить меню/рецепт, но не списывает запасы без действия пользователя.
OCR и распознавание изображений не реализованы и не имитируются.

### 3.7 Совместная жизнь
Общие цели (с историей достижения), список желаний, идеи занятий и планы выходных,
журнал приятных событий, личные заметки (приватные по умолчанию), совместные
привычки с отметками. Важные даты — ежегодные события календаря.

### 3.8 Документы
Метаданные (название, категория, дата, срок действия, напоминание, приватность),
загрузка/скачивание через контролируемый доступ, поиск, архивирование.
Хранилище — локальный том или S3-совместимое. Файлы никогда не публичны:
скачивание только по короткоживущей подписанной ссылке, выданной после проверки прав.

### 3.9 AI-ассистент
* Понимает русский язык, работает через строго ограниченный реестр инструментов.
* Контекст семьи и пользователя берётся из проверенной сессии, а не из аргументов.
* Чтение выполняется сразу; изменения — либо автоматически (простые явные действия,
  если разрешено настройкой семьи), либо через подтверждение (proposal с предпросмотром,
  сроком действия, защитой от повторного выполнения), либо запрещены.
* Память: контекст диалога, сводки, долгосрочные предпочтения (просмотр/удаление
  пользователем), приватные записи не попадают в общую память.
* Лимиты на число запросов и токенов в день; AI отключаем без влияния на остальное.

### 3.10 Telegram-бот
Команды `/start`, `/app`, `/help`, `/settings`, `/cancel`. Открывает Mini App,
доставляет уведомления, отвечает на AI-запросы, подтверждает действия кнопками.

### 3.11 Уведомления
Категории: события, платежи, просроченные задачи, новые задачи, изменения покупок,
цели, документы, системные. Настройки категорий, тихие часы, часовой пояс,
защита от дублей (`dedupe_key`), повторные попытки, статус доставки.
Партнёр не получает уведомлений о чужих приватных записях.

## 4. Нефункциональные требования
* Мобильный интерфейс внутри Telegram (iOS/Android), безопасные области, светлая и
  тёмная темы, отсутствие горизонтальной прокрутки, крупные элементы управления.
* Язык интерфейса — русский; структура i18n допускает английский и польский.
* Изоляция данных семей на уровне каждого запроса.
* Деньги — только Decimal.
* Идемпотентность операций, которые могут повториться (заголовок `Idempotency-Key`).
* Развёртывание: Docker Compose на одном VPS, HTTPS через Caddy.

## 5. Предположения (приняты по умолчанию)
1. Одна основная валюта на семью (по умолчанию `PLN`), без конвертации.
2. Переводы — только между счетами в одной валюте.
3. Сессия — непрозрачный bearer-токен (не cookie), см. `SECURITY.md`.
4. Синхронизация — периодический опрос (polling), без WebSocket.
5. Фоновые задачи — очередь в PostgreSQL (`FOR UPDATE SKIP LOCKED`), Redis — для
   ограничения частоты запросов.
6. AI-провайдер по умолчанию — OpenAI Chat Completions с tool calling; адаптер
   позволяет подключить другой провайдер.
