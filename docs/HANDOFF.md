# Family OS — как продолжить работу (новое устройство или новый аккаунт Claude)

Состояние на 27 октября 2026, версия **0.14.0**. Весь код, документы и история — в этом
репозитории; ничего важного не хранится только в старой сессии.

## 1. Как продолжить в Claude Code

1. Откройте claude.ai/code (или приложение Claude) под новым аккаунтом.
2. Подключите GitHub, если просит, и дайте доступ к репозиторию **yurypatsko-ctrl/Pohui**.
3. Начните сессию с этим репозиторием и веткой **`claude/family-os-telegram-app-hpkcnl`**
   (на ней всё рабочее; из неё же идёт деплой).
4. Первым сообщением можно написать: «Прочитай CLAUDE.md и docs/HANDOFF.md и продолжим».
   В `CLAUDE.md` — правила и обязательные проверки, здесь — что где лежит.

Секреты (пароль базы, токен бота, ключи хранилища, ключи Apple Pay) **в репозитории не
хранятся** и не нужны для продолжения разработки: они настроены в Render и Cloudflare.

## 2. Где что работает

| Что | Где | Примечание |
|---|---|---|
| Приложение (сайт, PWA) | https://my-family-app.pages.dev | Cloudflare Pages, собирается из `frontend/` при каждом push |
| Сервер (API + фоновые задачи + бот) | https://my-family-api.onrender.com | Render free, один сервис (`render.yaml`), деплой при изменении `backend/**` |
| База данных | Supabase (PostgreSQL, free) | строка подключения — только в Render → Environment |
| Файлы документов | Supabase Storage (S3) | ключи — только в Render |
| Telegram-бот | @my_family_bot | вебхук на сервер, секрет выводится из `APP_SECRET_KEY` |
| Не даёт серверу уснуть | GitHub Actions `keepalive.yml` | запрос к серверу каждые 10 минут |
| Проверки | GitHub Actions `ci.yml` | бэкенд, фронтенд, e2e — на каждый push |

Проверить, что всё живо: `/health/ready` на сервере должен ответить
`{"status":"ok","worker":"ok"}`.

Настройки сервера (имена, без значений) — в `render.yaml` и `.env.example`:
`APP_SECRET_KEY`, `DATABASE_URL`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`,
`STORAGE_*`, по желанию `OPENAI_API_KEY`/`AI_MODEL`, `JAKDOJADE_API_KEY`/`JAKDOJADE_API_SECRET`.
Менять `APP_SECRET_KEY` нельзя: от него зависят входы, push-уведомления и шифрование адресов.

## 3. Что умеет приложение

- **Финансы:** счета (общие и личные — личность задаётся счётом), операции, бюджет месяца,
  регулярные платежи, цели, импорт CSV, Apple Pay → расходы через Команды iPhone,
  логотипы 187+ магазинов.
- **Календарь:** события, напоминания, рабочие смены, польские праздники и торговые воскресенья.
- **Дом:** списки покупок с каталогом продуктов, задачи, кухня (продукты, рецепты, меню),
  документы со сроками, «Вместе» (цели, идеи, привычки).
- **Главная:** приветствие, «Листочек дня», погода «Забота», бюджет, «Продукты», «Мой маршрут».
- **«Забота на каждый день»:** утреннее сообщение с реальной погодой (CHANGELOG 0.12.0).
- **«Мой маршрут» и «Расписание»:** места (адреса зашифрованы), варианты поездки трамваем и
  автобусом по официальному расписанию Вроцлава, расписание всех линий и табло остановок —
  подробно в `docs/MY_ROUTE.md`.
- **Вход и уведомления:** Telegram Mini App; вне Telegram — вход с подтверждением в боте;
  установка на экран «Домой» (PWA); push-уведомления на экран блокировки, Telegram — запасной канал.
- **Семья:** приглашение партнёра через бота, роли, личные и общие данные.

Полная история — `CHANGELOG.md`; архитектура — `ARCHITECTURE.md`; безопасность —
`SECURITY.md`; дизайн — `docs/DESIGN.md`; установка с нуля — `docs/SETUP_GUIDE.md`,
`docs/RENDER_SUPABASE.md`, `docs/CLOUDFLARE_PAGES.md`.

## 4. Код

```
backend/   FastAPI, SQLAlchemy, Alembic, aiogram — app/modules/<раздел>/, тесты в tests/
frontend/  React 19, Vite, Tailwind, TanStack Query — src/features/<раздел>/, тесты в tests/
docs/      инструкции; CLAUDE.md — правила для Claude
```

Локальный запуск — `README.ru.md` («Быстрый старт для разработки»). Все проверки перед
отправкой перечислены в `CLAUDE.md` (их же запускает CI).

## 5. Последняя полная проверка (27.10.2026)

- Бэкенд: ruff, форматирование, mypy — без замечаний; **226 тестов** прошли; модели и
  миграции совпадают; известных уязвимостей в зависимостях нет.
- Фронтенд: TypeScript без ошибок; **154 теста** прошли; production-сборка; `npm audit` — 0 уязвимостей.
- E2E (реальный сервер + браузер): 2 сценария семьи и приватности прошли.
- Проход по всем 29 экранам за двух членов семьи (и 4 главным в тёмной теме) на локальном сервере с
  настоящим расписанием Вроцлава: ни ошибок, ни сбоев запросов, ни горизонтальной прокрутки,
  ни битых картинок; личные данные партнёру не видны.
- Рабочий сервер: здоров, фоновые задачи работают, тестовый вход выключен, личные разделы
  без входа закрыты (401), вебхук без секрета отклоняется.
